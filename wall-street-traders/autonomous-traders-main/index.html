SECURITY

Threat model (harden v5)

MAIN ONLY

Trust boundaries. Browser holds Arcus ed25519 signing keys in sessionStorage only — Edge rejects any private-key fields. Wallet ownership is proven via one-time personal_sign challenges (main_auth_nonces) for activate/revoke. Every placeOrder/cancel re-checks NFT ownerOf on Robinhood Chain and auto-revokes if transferred. Noble ed25519 is vendored locally (CSP blocks random CDNs).

Caps. Hard max_notional_usd with drip spent tracking. Hard max_loss_usd via Arcus mainnet mids mark check (realized + unrealized + open adverse). Env forced to Arcus TESTNET unless caps.allow_mainnet===true.

Orders. Short GTT (15–60 min, default 30). Idempotency keys required. Cancel requires signed op=2 payload + headers; Edge proxies to testnet cancelOrder. Actor labeled holder vs agent.

CORS. Default allowlist (commitprotocol.org + localhost). Override via Edge secret CORS_ORIGIN_ALLOWLIST in Supabase Dashboard → Project Settings → Edge Functions → Secrets (comma-separated Origins). Never reflects *.

Residual risks (after this pass). XSS that bypasses CSP can still read the signing key while Pilot/session is open (key lives in page memory / sessionStorage). Mark PnL is a rough estimate (not full exchange position reconciliation). Mainnet placeOrder still possible if an activation has allow_mainnet. file:// Origin null is optionally allowlisted.
